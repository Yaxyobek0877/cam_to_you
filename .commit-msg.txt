fix(v0.1.9): reject invalid stream keys + clear YouTube instructions

Latest error: rtmp://a.rtmp.youtube.com/live2/live2
Saved key was just "live2" — that's YouTube server's path segment,
NOT the actual stream key. User likely entered an incomplete URL
like "rtmp://a.rtmp.youtube.com/live2" (no actual key after).

BACKEND validation:
- service.go: new validateStreamKeyShape() rejects:
  - Keys shorter than 10 chars (real keys are 16-25)
  - Known path segments: "live", "live2", "app", "rtmp", "stream",
    "flv", "channel", "ingest"
- Error message guides user: "YouTube Studio → Go Live → Stream key"

FRONTEND improvements:
- StreamKeyField now validates as user types
  - Green ✓ "Stream key formati to'g'ri ko'rinmoqda" if valid
  - Red ❌ with specific reason if invalid
  - URL preview shows masked key in green/red based on validity
- New YouTubeKeyInstructions collapsible component
  - Direct link to YouTube Studio
  - Numbered 6-step instructions
  - Shows expected key format: xxxx-xxxx-xxxx-xxxx-xxxx
- Better placeholder: 5-group format (more accurate)

Now users get clear, actionable feedback BEFORE saving instead of
cryptic FFmpeg errors after attempting to stream.
