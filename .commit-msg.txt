fix(v0.1.8): auto-strip RTMP URL prefix from stream key

Root cause of "I/O error" (exit 0xffffffffb):
User entered full URL "rtmp://a.rtmp.youtube.com/live2/KEY" in Stream Key
field instead of just "KEY". Our code then prepends the base URL again,
producing the duplicated:

  rtmp://a.rtmp.youtube.com/live2/rtmp://a.rtmp.youtube.com/live2/KEY

FFmpeg fails to open this invalid URL with I/O error.

FIXES:

Backend (defensive):
- stream/service.go: sanitizeStreamKey() — if key starts with rtmp:// or
  rtmps://, extract just the part after the last slash before saving
- db migration v2: cleans up existing rows where stream_key looks like
  an RTMP URL (so users don't need to manually re-edit existing streams)

Frontend (user-friendly):
- New StreamKeyField component with:
  - Auto-strip on type (user can paste full URL, only key kept)
  - Live URL preview: shows final "<base>/<masked-key>" so user sees
    exactly what will be used
  - Warning hint when user pastes RTMP URL
  - Per-platform instructions (YouTube Studio path, etc.)

Now both scenarios work:
- User pastes "rtmp://a.rtmp.youtube.com/live2/abc-def" → saved as "abc-def"
- User pastes "abc-def" → saved as "abc-def"
