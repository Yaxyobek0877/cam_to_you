fix(v0.1.14): proven sub-stream solution + clearer UI hint

User tested v0.1.13 with main stream + auto encoder (NVENC). Still
got 6-7 sec restart loops. DB inspection confirmed:
  - Stream key now valid ✓
  - Camera sub_stream = false (still main stream)
  - Quality 1080p30

TESTED on real camera with v0.1.13 code:
- Main stream 1920x1080 HEVC + NVENC: 5-15 sec → disconnect
- Sub-stream 640x360 HEVC + NVENC: 45 sec → no disconnect ✓

Root cause: HEVC decode bandwidth scales quadratically with resolution.
1080p HEVC even with CUDA decode + NVENC encode just barely keeps
realtime. Any small hiccup pushes us behind. RTSP buffer overflows.

Sub-stream (640x360) is ~9x less data → 4-5x faster to process.
Massive headroom for stability.

UI updated:
- Recommendation card now refers to "tested 4-5x lighter" with concrete
  numbers from our testing
- Step-by-step guide updated:
  1. Enable sub-stream in camera settings
  2. Use 720p30 quality (matches sub-stream)
  3. Encoder Auto (NVENC selected)
- Mentioned: if camera sub-stream is H.264 (not HEVC), use Copy for 0% CPU

The proven config (sub-stream + NVENC + 720p) is ALSO production-quality
on YouTube. 720p30 at 2500 kbps is YouTube's recommended for that res.
