## 🚨 v0.1.17 buzuq edi — kechirim so'rayman

v0.1.17 dagi RTSP stabillik bayroqlari **xato edi**:
- `-stimeout` — yangi FFmpeg builds'da olib tashlangan
- `-rw_timeout` — xuddi shunday
- `-probesize 32` — juda kichik, codec parametrlarini topib bo'lmaydi

Natija: `Error splitting the argument list: Option not found` xatosi va stream umuman boshlanmasdi.

**Men buni release qilishdan oldin sinab ko'rmagan edim.** Bu noto'g'ri edi. v0.1.18 da har bir flag **kameradan-kameragacha haqiqiy oqim bilan sinab ko'rilgan**.

## ✅ v0.1.18'da nima haqiqatan ishlaydi

### To'g'ri RTSP flaglari (testdan o'tdi)

```
-timeout 10000000          (RTSP socket I/O timeout, mikrosek)
-reorder_queue_size 0      (kichik buffer)
-fflags +nobuffer+discardcorrupt
```

Aniq ishlaydigan flag'lar — `probesize` va `analyzeduration` default qoldirildi.

### Kameradan test natijalari

| Konfiguratsiya | Natija | Eslatma |
|---------------|--------|---------|
| **Sub Stream (HEVC 640×360)** + NVENC | ✅ 23+ sek barqaror | Tavsiya |
| **Main Stream (H.264 1920×1080)** + NVENC | ❌ 2-7 sek uzildi | Kamera sessiya cheklovi |

**Xulosa**: Hikvision kameraning **Main Stream**'i transcoding paytida sessiya cheklovi tufayli darrov uziladi. **Sub Stream**'da 23+ sek barqaror ishlaydi. Foydalanuvchilar:
1. Cameras sahifasida **"Sub-stream ishlatish"** belgilashlari kerak
2. Yoki kamera web UI'da Main Stream uchun H.265 emas H.264 sozlash

### Restart delay 1s → 3s

Kamera RTSP sessiyani 2-3 sek tutib turadi. Darrov qayta urinish — eski sessiya qoldig'iga uradi. Endi 3 sek minimum.

### Avtomatik tavsiya tizimi (v0.1.17 dan)

Logs sahifasida har stream uzilganida aniq tavsiya beriladi:

```
🔍 FFmpeg chiqdi (exit=0, state=stopped). Oxirgi qatorlar:
🎥 Kamera RTSP sessiyani yopdi (EOF). Bu odatda Hikvision sessiya cheklovi.
   YECHIM: kamera web UI → Configuration → Video/Audio → Sub Stream → 
   Video Encoding'ni H.264 ga o'zgartiring. Keyin Cam2You'da Encoder = Copy.
  └ [in#0/rtsp @ ...] Failed reading RTSP data: End of file
```
