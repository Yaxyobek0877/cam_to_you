## ✅ Tuzatishlar

### 1. **Real-time stream progress UI'da ko'rinadi**

Endi FFmpeg statistika qatorlari (`frame=N fps=N bitrate=N`) parse qilinadi va Logs sahifasida ko'rsatiladi:

```
✅ Stream ishlamoqda — YouTube'ga ma'lumot yuborilmoqda
📡 25 fps · 4500kkbps · 00:00:05.00 efirda
📡 26 fps · 4350kkbps · 00:00:10.00 efirda
📡 26 fps · 4280kkbps · 00:00:15.00 efirda
```

**Yangi event tiplari:**
- `live` — birinchi frame YouTube'ga jo'natilganida (bir martalik)
- `progress` — har 5 sek'da statistika

Foydalanuvchi endi stream haqiqatdan ishlayotganini darrov ko'radi.

### 2. **libopenh264 encoder argumentlari to'g'rilandi**

`builder.go`:
```diff
case EncoderOpenH264:
+   "-rc_mode", "bitrate",         // default "quality" emas — target bitrate'ni hurmat qilsin
+   "-allow_skip_frames", "1",     // bitrate qondirish uchun frame skip ruxsat
    "-b:v", strconv.Itoa(...)+"k",
    "-g", gop,
+   "-keyint_min", gop,            // qat'iy keyframe oralig'i (YouTube majburiy)
    "-profile:v", "main",
    "-pix_fmt", "yuv420p",
+   "-flags", "+global_header",    // FLV muxer to'g'ri extradata yozsin
+   "-bsf:v", "dump_extra=freq=keyframe", // har keyframe oldida SPS/PPS qayta yozish
```

**Natija:** `bEnableFrameSkip = 0...` warning **yo'qoldi**.

### 3. **Scale filter qo'shildi**

Avval `-vf format=yuv420p` faqat pixel format'ni o'zgartirardi. Agar kamera **sub-stream** 640x360 yuborgan bo'lsa, output ham 640x360 chiqardi (foydalanuvchi 1080p tanlagan bo'lsa ham).

Endi:
```
-vf scale=W:H:force_original_aspect_ratio=decrease:in_range=full:out_range=tv,
    pad=W:H:(ow-iw)/2:(oh-ih)/2:color=black,
    format=yuv420p
```

- **scale**: kamera nima yuborgan bo'lsa, sozlangan W×H ga olib boradi
- **force_original_aspect_ratio=decrease + pad**: aspect ratio saqlanadi, qoldiq qora bilan to'ldiriladi (sun'iy cho'zish yo'q)
- **in_range=full → out_range=tv**: Hikvision PC range → YouTube TV range to'g'ri konvertatsiya

### 4. **FFmpeg log scanner `\r` ni qo'llab-quvvatlaydi**

FFmpeg statistika qatorlarini `\r` (carriage return) bilan yozadi — ekranda bir qatorni qayta-qayta yangilash uchun. Eski scanner faqat `\n`'da to'xtardi, natijada barcha `frame=` yangilanishlari yagona ulkan string sifatida kelardi.

`runner.go` da `splitLinesCR` SplitFunc qo'shildi — endi har bir yangilanish alohida qator sifatida o'qiladi. Bu real-time progress event'lari uchun ZARUR edi.
