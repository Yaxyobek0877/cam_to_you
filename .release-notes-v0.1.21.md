## 🐛 v0.1.21 — Asl xato topildi: YouTube hech qachon Cam2You stream'ini ko'rmas edi

### Vaziyat

v0.1.20 dan keyin foydalanuvchi UI'da progress ko'rar edi:
```
✅ Stream ishlamoqda — YouTube'ga ma'lumot yuborilmoqda
📡 26 fps · 1041 kbps · 00:00:07 efirda
```

Lekin YouTube hali ham "Translatsiya kelmayapti" deb yozar edi. Foydalanuvchi shubha qildi:
> "ozimni boshqa platformam da sinab korgandim u yerda key bilan stream yoqib bera olayabdi"

Ya'ni — **aynan o'sha YouTube key boshqa software (OBS) bilan ishlardi**, faqat Cam2You bilan emas.

## 🔬 Diagnostika

5 ta turli FFmpeg konfiguratsiyasini ayni kamera + ayni YouTube key bilan sinab ko'rdim:

| # | Encoder | Args | Warning |
|---|---------|------|---------|
| 1 | h264_mf | nv12, cbr | (toza) |
| 2 | libopenh264 | v0.1.20 args (profile=main + global_header + dump_extra) | UNSPECIFIC profile |
| 3 | libopenh264 | profile=main + minimal | UNSPECIFIC profile |
| 4 | libopenh264 | profile=YO'Q (default) | (toza) |
| 5 | libopenh264 | profile=high | (toza) |

**Aybdor topildi:**
```
[libopenh264] Warning:layerId(0) doesn't support profile(578),
              change to UNSPECIFIC profile
```

`-profile:v main` → libopenh264 ichki kodi PRO_MAIN=77 ga xaritalashga harakat qiladi, lekin layer constraint check'ida fail bo'ladi va **UNSPECIFIC profile (profile_idc=0)** ga o'tib qoladi.

**Profile_idc=0** = noma'lum profile. **YouTube ingest server packet'larni qabul qiladi** (RTMP-darajada ishlaydi), lekin **video dekoderi profile_idc=0'ni rad qiladi** → "broadcast yo'q" holati. FFmpeg "stream ishlamoqda" deydi, YouTube "hech narsa kelmadi" deydi — ikkalasi ham haqiqat aytmoqda.

## ✅ Tuzatishlar

### 1. `libopenh264` profile: main → high

```diff
- "-profile:v", "main",
+ "-profile:v", "high",
```

PRO_HIGH=100 libopenh264 ichida to'g'ri xaritalanadi, layer check'dan o'tadi, UNSPECIFIC fallback ishlamaydi. YouTube `profile_idc=100`'ni mukammal dekod qiladi. OBS va boshqa software ham High profile ishlatadi.

### 2. `+global_header` va `dump_extra` olib tashlandi

v0.1.20 da "ehtiyot uchun" qo'shilgan edi. Aslida FLV muxer default holatda SPS/PPS'ni to'g'ri joylashtiradi. Bu bayroqlar ba'zi YouTube ingest server'larida muammo qilar edi.

### 3. **YANGI**: `h264_mf` (Windows MediaFoundation) qo'llab-quvvatlash

Streamlar sahifasida endi yangi encoder tanlanishi mumkin:
> **MediaFoundation (Windows native — YouTube uchun tavsiya)**

Bu Microsoft'ning o'rnatilgan H.264 encoder'i — OBS, vMix va boshqa professional software ishlatadi. YouTube to'liq qabul qiladi, profile mismatch yo'q.

### 4. Auto-tartib o'zgardi: `MediaFoundation > OpenH264`

`encoders.go` BestH264():
```diff
case e.X264:
    return "libx264"
+ case e.MediaFound:
+   return "h264_mf"     // ↑ endi yuqoriroq tartibda
case e.OpenH264:
    return "libopenh264"
- case e.MediaFound:
-   return "h264_mf"
```

GPU yo'q va `libx264` mavjud bo'lmagan tizimlarda endi h264_mf default bo'ladi (libopenh264 emas).

## 💡 Foydalanuvchi uchun nima qilish kerak

Agar Cam2You yangilab `libopenh264` bilan ishlatayotgan bo'lsangiz, **avtomatik tuzaladi** — `-profile:v high` endi to'g'ri xaritalanadi.

Yoki tezroq variant: **Streamlar sahifasida → "yt" stream → Tahrirlash → Encoder → "MediaFoundation"** ni tanlang.
