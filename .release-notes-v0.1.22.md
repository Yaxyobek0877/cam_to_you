## 🔇 v0.1.22 — Audio'siz kamera YouTube'da ko'rinmas edi

### Asl muammo

v0.1.21 dan keyin foydalanuvchi: kamera streami 1+ daqiqa ishlaydi, UI'da `📡 27 fps · 2200 kbps · 00:01:03` ko'rinadi, lekin YouTube Studio'da **hech narsa paydo bo'lmaydi**.

Lekin "test pattern" (audio + video) bilan to'g'ridan-to'g'ri test qilingach, YouTube **darrov ko'rsatdi**. Kamera bilan esa ko'rsatmas edi.

## 🔬 Aybdor topildi

Hikvision **sub-stream'da audio yo'q** (faqat main stream'da bor). FFmpeg `-map 0:a?` orqali optional audio mapping qiladi, lekin kamera audio'siz bo'lsa, FFmpeg **video-only** stream yuboradi.

**YouTube RTMP server bunday stream'larni packet-darajada qabul qiladi**, lekin video dekoderi **audio yo'q stream'ni "broadcast" deb tan olmaydi** → Studio "Translatsiya kelmayapti" ko'rsatadi. FFmpeg "stream OK" deydi, YouTube "broadcast yo'q" deydi.

Test pattern bizning testimizda **sine 440Hz tone** bilan birga edi — shu sababli YouTube ko'rdi.

## ✅ Tuzatishlar

### 1. Har doim **silent audio** inject qilamiz

`builder.go` da `Build()` funksiyasi endi kamera input'lardan keyin `anullsrc` (jim audio) input qo'shadi:

```go
args = append(args,
    "-f", "lavfi",
    "-i", "anullsrc=channel_layout=stereo:sample_rate=44100",
)
```

Audio mapping `buildAudioArgs` `-map N:a` (N = kameralar soni) bilan jim audio'ni AAC 128k stereo qilib yuboradi. YouTube endi har doim audio+video oqimini ko'radi va "broadcast" deb tan oladi.

> **Eslatma**: Kelajakda `cfg.Audio.Mode == "first"` paytida kamera audio'sini probe qilib, mavjud bo'lsa shu ishlatiladi. Hozir DOIM jim audio (eng ishonchli yo'l).

### 2. **Hardware encoder real probe**

`encoders.go` da `probeEncoder()` funksiyasi qo'shildi. Endi NVENC/QSV/AMF/MediaFoundation har biri **runtime'da haqiqatan sinab ko'riladi** (320×240 test frame). FFmpeg binary'da nom borligi yetarli emas — driver/GPU/lisenziya yo'q bo'lsa, "yo'q" deb belgilanadi.

**Sizning tizimingizda probe natijasi:**
```
✅ h264_nvenc — ishlaydi (NVIDIA GPU)
✅ h264_qsv   — ishlaydi (Intel iGPU)
❌ h264_amf   — DLL amfrt64.dll yo'q (AMD GPU yo'q)
✅ h264_mf    — ishlaydi (Windows native)
✅ libopenh264 — ishlaydi (CPU)
```

Foydalanuvchi UI'da endi ishlamaydigan encoderlarni tanlay olmaydi.

### 3. CPU encoder uchun yangilik

- `Stream → Encoder` dropdown'da endi `libopenh264 (CPU fallback — eski)` o'rniga "CPU sifatli encoder" deb ko'rinadi
- Auto rejimda agar GPU yo'q bo'lsa **libopenh264** ishlatiladi (h264_mf'dan oldin) — chunki MF ham ba'zan HW-backed
